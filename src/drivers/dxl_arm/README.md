# dxl_arm：CUAV 7-Nano 三舵机串口控制

本驱动用于在 PX4 飞控上直接与 DYNAMIXEL 舵机通信。目前通过 NSH 控制台检测 ID 1、2、3 是否在线，同步设置三台舵机的目标位置，并读取当前位置。

**当前状态**：作者已在实际硬件台架上实现控制效果；代码已通过 CUAV 7-Nano 固件的完整编译、链接和打包。下文示例用于说明操作，不是实测日志。

## 在官方 PX4 上改了什么

基于官方 `release/1.18` 分支，基线提交为 `8303efda43`。功能修改集中在以下四个文件，另外补充了本说明和仓库首页入口：

| 文件 | 改动与作用 |
| --- | --- |
| [`dxl_arm.cpp`](dxl_arm.cpp) | 新增 `dxl_arm` 命令，实现串口初始化、Protocol 2.0 报文收发和三舵机控制 |
| [`CMakeLists.txt`](CMakeLists.txt) | 将驱动接入 PX4 模块编译，注册 `dxl_arm` 命令 |
| [`Kconfig`](Kconfig) | 新增 `DRIVERS_DXL_ARM` 驱动选项 |
| [`boards/cuav/7-nano/default.px4board`](../../../boards/cuav/7-nano/default.px4board) | 添加 `CONFIG_DRIVERS_DXL_ARM=y`，使默认固件包含驱动 |

实现中加入了 CRC16 校验、Protocol 2.0 字节填充与去填充、按 Length 字段解析状态包、过滤合法指令回显，以及非阻塞串口短写和错误处理。运动参数会检查格式和范围，写入目标后会逐台核对读回值。

## 当前硬件与配置约定

| 项目 | 当前代码配置 |
| --- | --- |
| 飞控与编译目标 | CUAV 7-Nano，`cuav_7-nano_default` |
| 串口 | TELEM1，对应 `/dev/ttyS5` |
| 通信参数 | 57600 baud、8N1，无硬件流控 |
| 舵机协议 | DYNAMIXEL Protocol 2.0，使用 XL430 对应的寄存器地址 |
| 舵机 ID | 1、2、3 |
| 目标位置 | 整数 `0～4095`，需与实际工作模式、舵机限位及机械臂可用范围一致 |

连接关系为：**TELEM1 → 匹配的串口/舵机总线转换接口 → 舵机总线**。按实际设备确认供电、共地与接口电平；不要把飞控串口当作舵机电源。TELEM1 应留给本驱动使用，避免 MAVLink 等模块同时占用。

串口、波特率和 ID 目前在代码中固定；更换设备或配置时需修改源码并重新编译。代码不会自动设置或核实舵机的工作模式。

## 编译与运行

准备好 PX4 对应的开发环境后：

```bash
git clone --recursive --branch dxl-arm https://github.com/supsmwhite/PX4-Dynamixel-Arm.git
cd PX4-Dynamixel-Arm
make cuav_7-nano_default
```

生成的固件位于 `build/cuav_7-nano_default/cuav_7-nano_default.px4`。将其烧录至对应飞控后，在 QGroundControl 的 MAVLink Console 或其他 NSH 控制台中运行下列命令。

| 命令 | 功能与输出 |
| --- | --- |
| `dxl_arm ping` | 依次检测 ID 1、2、3，输出在线状态、型号、固件版本和状态包错误码 |
| `dxl_arm read` | 同步读取三台舵机的当前位置（地址 132），输出位置和状态包错误码 |
| `dxl_arm move <pos1> <pos2> <pos3>` | 广播使能力矩，向 ID 1、2、3 同步写入目标位置（地址 116），再读回目标寄存器进行核对 |

建议先运行 `ping` 和 `read` 确认通信。运动命令的写法例如：

```text
dxl_arm move 2048 2048 2048
```

这里的 `2048` 仅为语法示例，运行前应换成适合当前机械臂、且已确认可达的位置。`move` 会广播开启总线上舵机的力矩，测试总线应只连接预期控制的设备。

三台设备的目标寄存器均与请求值一致且状态包错误码为零时，程序输出“已下发并读回确认目标位置”。**这表示目标值已读回一致，不表示机械臂已经到位**；可用 `read` 观察实际位置变化。

## 验证范围与已知限制

- 已完成完整固件构建；模拟串口回归覆盖了 CRC、非法参数、短写、`EAGAIN`、分段接收、带字节填充的回复及目标值读回。作者另已在硬件台架上实现控制效果，当前仓库未附演示视频或实测日志。
- 当前入口为手动 NSH 命令；尚未接入上层自动控制流程，也没有自动到位判断或停止/失能命令。
- 两个已识别的边界问题待完善：持续 `EINTR` 时写入超时检查不完整；重复 ID 回复可能使接收提前结束，误报未收齐设备。

审阅时可从 `dxl_arm_main()` 开始，按“参数检查 → 力矩使能 → 同步写入 → 读回校验”查看控制流程。全部定制差异可用 `git diff 8303efda43 HEAD` 查看。
